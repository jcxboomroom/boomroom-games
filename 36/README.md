# 第 36 款 · Tetris Battle：爆爆方塊攻防

本款以堆疊與消行為核心，讓玩家透過保留方塊、預判下一塊與維持空隙，將消行轉成攻擊。桌面、手機直向與橫向均使用同一個本機規則引擎。

## 模式與操作

- 單人馬拉松：消除 150 行完成，每 10 行提高下落速度。
- 單人 40 行衝刺：完成 40 行，記錄此裝置最高分與最佳完成時間。
- 房間攻防：2–10 位正式 Session 參賽者，全員準備後由房主開始；每局同一七袋序列、3 秒倒數、最多 3 分鐘。最後存活者勝出；逾時依存活、攻擊、分數、消行比較，淘汰者依存活時間排序，相同成績並列。
- 鍵盤：← → 移動、↓ 加速、↑ / X 右轉、Z 左轉、C / Shift 保留、Space 硬降、P 暫停單人。
- 觸控：下方按鈕支援長按移動／下降與多指操作；棋盤輕點旋轉、左右滑動移動、向下長滑硬降。

七袋、五個 NEXT、HOLD、Ghost、SRS 牆踢、500ms 鎖定延遲與最多 15 次延遲重置均由 `engine.js` 實作。消除雙／三／四行送 1／2／4 行；T-spin、Back-to-back、Combo 與 All Clear 追加攻擊。攻擊先抵消待收垃圾，剩餘送到選定的存活對手；垃圾等待 1.2 秒，未消行的鎖定後上升。淘汰後可點選對手，在主棋盤觀戰。

## SDK 與信任邊界

入口直接依序載入共用 SDK、引擎、房間控制器與 UI。內嵌頁面以 `whenReady()` 等待真實對局，只有 `PLAYING` 才能操作；獨立頁面只提供明確的本機單人挑戰，不建立假帳號或假房間。

`room.js` 使用經 SDK 與 APP 認證的 sender 作身分，限制參賽名單、同一 Session／局次、房主控制與數值／棋盤結構。事件包括 `TB_READY`、`TB_CONTROL`、`TB_STATE`、`TB_ATTACK`、`TB_GARBAGE_ACK`、`TB_SYNC_REQUEST`、`TB_SYNC`。操作立即在本人棋盤呈現，棋盤每 300ms 更新，房主每秒送摘要；垃圾附帶去重鍵，接收確認前保留在房主摘要，攻擊意圖亦會有限重送。

5 秒沒有房主消息顯示同步中並停止操作；可重試同步。25 秒沒有參賽者消息視為離線淘汰。房主離開或正式 Session 結束會中斷對局。存檔依 Session、玩家與局次隔離；重新載入需再次握手，並等待房主同步。缺少有效的本局個人存檔時轉為觀戰，不能用新棋盤接替已進行的局次。

此為 **casual relay**：房主協調休閒結果，規則、分數及排名沒有正式服務端驗證，也没有跨裝置持久存檔。`completeRound()` 保留結果與再玩；`leaveGame()` 才請求退出；不呼叫 `gameOver()`、購買、派彩或可信排行。音效與音樂使用本地 Web Audio 合成，支援分開即時靜音；震動使用 SDK revision 4 的 session-bound 原生橋接／瀏覽器能力，可獨立關閉。
