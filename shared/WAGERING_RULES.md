# BoomRoom 遊戲加碼與獎池規範（必讀）

本文件是所有 BoomRoom 遊戲設計、接入、修正與驗收的產品規範。開始設計或改動任何遊戲前，必須先閱讀本文件，再閱讀 [`SDK_API.md`](SDK_API.md) 與該遊戲的伺服器契約。PR／交付說明應註明是否涉及入場費、加碼與獎池；不涉及也要明確寫「不支援加碼」。

## 固定入場費與自願加碼是兩筆不同的事

- 一般遊戲目前每位真人的固定入場費是 **100 銀幣**，由遊戲開局的伺服器流程收取；特定遊戲若有正式例外，以伺服器目錄和後端為準。它是入場費，不是加碼，不得併入對賭獎池或在 UI 混成一個下注金額。
- **額外加碼完全自願**，是入場費之外的另一筆金額。玩家可投 0，或選擇任一可用的非負整數；不得硬編碼 100／500／1000 等投注檔位。投票或確認前，畫面須分開顯示固定入場費、目前錢包餘額、扣除入場費後可用的加碼上限、每人候選加碼與預估獎池。
- AI 只能加入**不加碼的練習局**；AI 不投票、不確認、不出資，也不領取銀幣獎池。入場費是否適用仍依該遊戲正式伺服器政策顯示，不能把 AI 練習誤稱為已驗證的真人競賽或獎勵局。

## 投票與全員同意

1. 每位真人都可用滑桿或直接輸入整數金額。伺服器以同一真人參賽名單的可用餘額計算上限：`max(0, min(每位真人的錢包餘額 − 尚未扣除的固定入場費))`。如果入場費已由正式開局交易扣除，就以扣除後的實際餘額為基礎，不得再扣一次。
2. 所有真人都提交投票後，票數最多的金額成為候選金額；同票時取較低金額。候選金額只是一項提案，不代表玩家已同意或已扣款。玩家未投票時不得由房主代投，也不得推定同意。
3. 候選金額公布後，每位真人都必須明確確認同一個候選金額，才能開局。任何人拒絕、變更投票、離開、名單改變、候選金額／設定版本改變或確認逾時，都要使原確認失效；重新投票／確認或取消本次開局。不得以多數決強迫少數玩家下注，也不得把房主的開始操作當成全員同意。
4. 玩家可以一致確認 0 加碼；這代表只付已明確顯示的固定入場費，不建立加碼獎池。若遊戲不實作伺服器權威的投票與扣款協議，就必須停用加碼 UI 與客戶端扣款／派獎宣稱。

## 開局扣款必須由伺服器原子完成

- 投票時顯示的上限只是依當時餘額計算的提示。開局時伺服器必須鎖定同一局全體真人的錢包列（以穩定順序鎖定），重新讀取餘額、參賽名單、提案版本與每人明確確認狀態。
- 伺服器再次確認每位真人都能支付固定入場費與同額加碼。若入場費尚未入帳，依 `扣款前餘額 ≥ 100 + 候選加碼` 檢查；若入場費已在此交易前正式扣除，依 `目前餘額 ≥ 候選加碼` 檢查。不得重複收取入場費。
- 只有全員檢查成功，伺服器才能在同一資料庫交易中完成必要扣款、建立唯一帳本流水與獎池紀錄，並把對局狀態切到可開始。錢包扣款、獎池紀錄或對局狀態任一步失敗，整筆交易必須回滾；任何一人不足就取消此次開局，不能部分扣款或留下半個獎池。
- 所有命令須綁定已驗證的玩家身分、房間／Session、局次與提案版本，並以唯一冪等鍵防重播。客戶端餘額、票數、勝負、扣款或派獎結果都不是權威依據。

## 獎池、名次與顯示

- 在玩家投票前，遊戲必須說明本款採用的排名方式，以及獎池按該排名方式如何分配；金額及排名顯示要能讓玩家在確認前知道自己同意的規則。若規則由玩家在遊戲內選擇，也要把選擇版本綁定到全員確認。
- 加碼獎池只由實際成功扣下的真人加碼組成，固定入場費另按平台／創作者既有政策處理。由伺服器權威排名套用已公布／已選定的分配規則，處理並列名次、餘數、無有效排名、取消及中斷；不可讓遊戲 HTML 傳入任意獲獎者或 `winAmount` 就直接發幣。
- 結算必須冪等且留有可核對的伺服器帳本／收據。中斷或無法安全結算時，依遊戲後端契約整池退還或採用已公告的明確規則；不得部分支付後再宣稱整池結算成功。UI 只有收到伺服器權威收據後才能顯示已入帳。

## 共用 SDK 能力邊界

`boomroom-sdk.js` 提供房間握手、事件傳輸與 Session 生命週期，**目前沒有通用的加碼投票、全員確認、錢包鎖定或獎池結算 API**。`sendGameEvent()`、`gameOver()`、`completeRound()` 都不能授權扣幣、證明名次或發獎。官方 Tetris Battle 有專屬的伺服器端投票／確認／鎖錢包實作可供參考；其零加碼也要求全員投票與確認；這項特定引擎的實作不代表其他遊戲已具備同樣能力。每款遊戲仍須逐項對照並通過本文件的驗收。

任何新遊戲要支援真實加碼，必須先定義並審查伺服器權威協議，再實作 APP／後端／持久化／回歸測試及 UI。單靠共用 SDK 或 UGC 事件轉送時，遊戲只能不加碼遊玩；不得模擬錢包扣款、投票共識或獎池派發。

## 開發與驗收必查

- [ ] 遊戲設計與 Codex 開發提示已先閱讀本規範。
- [ ] 固定入場費與加碼在資料模型、UI、帳本和獎池完全分開。
- [ ] 整數滑桿／輸入支援任意金額，上限由全體真人扣除入場費後的可用餘額動態計算，並有伺服器開局重查。
- [ ] 票最多者勝出，同票取較低額；所有真人各自確認同一候選額，拒絕／變更／離場／版本改變會撤銷舊確認。
- [ ] 鎖定全體真人錢包並在單一交易中全成或全退；測過一人不足、重複命令、併發花費及資料庫失敗。
- [ ] 開局前顯示排名與分池規則；服務端依該規則冪等結算，客戶端不能給自己發幣。
- [ ] AI 只出現在明確標示、加碼為 0 的練習局。
- [ ] 若本款沒有完整伺服器權威協議，已停用所有真實加碼與獎勵宣稱。
